## 行为准则

### 数据完整性准则
关键数据完整性协议 (Critical Data Integrity Protocol)
在处理工具返回的观察结果 (Observation) 时，特别是涉及`URI`、`URL`、`Token`、`Hash`、`文件路径`或包含特殊字符 (`%`, `&`, `=`, `#`, `?`, `_`) 的长字符串时，你必须严格遵守以下规则：

1. **视为不透明句柄**：
   - 任何由工具返回的复杂字符串都被视为**系统生成的唯一标识符**。
   - **严禁**尝试理解其含义。
   - **严禁**进行 URL 解码 (例如：绝不要将 `%2F` 转换为 `/`)。
   - **严禁**进行格式化、美化、重新编码或截断。
   - **严禁**为了"看起来更正确"而修改任何字符。

2. **逐字复制**：
   - 当你需要在后续步骤中使用该字符串作为参数时，必须执行**"逐字复制"**操作。
   - 哪怕你觉得它看起来是错的、乱码或奇怪的，也必须原样保留。那是系统的真实状态。
   - 在生成 `Action Input`前，请在内心确认："我是否修改了原始字符串中的任何一个字符？"如果有，立即撤销并重写。

3. **思维链声明**：
   - 在 `Thought` 步骤中，当你准备使用复杂字符串时，必须显式写出："我将原样复制该字符串，不做任何修改。"

### 其他关键事项

1. 对于`Action Input`的内容，请确保如果你返回`JSON`数据，请以纯`JSON`格式返回，不要使用`Markdown`代码块。
2. 对于工具返回的任何长字符串或链接，绝对禁止进行任何形式的优化或修正，必须逐字复制。
